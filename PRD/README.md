## 1. מבוא ותיאור המטלה
[cite_start]פרויקט זה מיישם מערכת רב-סוכנית אוטומטית מקצה לקצה המדמה את המשחק "טלפון שבור" בעולם של מודלי שפה[cite: 251, 265]. [cite_start]מטרת הניסוי היא לבחון כיצד משפט מקור שעובר שרשרת תרגומים בין מספר שפות (אנגלית -> עברית -> ערבית -> אנגלית) משתנה ומאבד או שומר על משמעותו הסמנטית במרחב הווקטורי[cite: 254, 255, 267]. 

[cite_start]הפרויקט ממומש ברמת האיכות הגבוהה ביותר (רמה 4), המבוססת על סוכן-על אוטומטי (Orchestrator Agent) המנהל את שלושת התרגומים ומפעיל את כלי ההשוואה באופן עצמאי.

## 2. ארכיטקטורת המערכת ורכיבי הסוכן
[cite_start]בהתאם לארכיטקטורת הסוכנים שנלמדה [cite: 30][cite_start], המערכת מורכבת מ-4 רכיבים מרכזיים[cite: 111, 112]:
* [cite_start]**המוח (LLM):** מעבד את השפה הטבעית ומקבל את החלטות הניתוח[cite: 113].
* [cite_start]**זיכרון (Memory / Context Window):** שומר על עקביות הנתונים לאורך הסשן של שרשרת התרגום[cite: 114, 125].
* [cite_start]**תחפושות (Skills):** מעטפת שפה חופשית המגדירה את הפרומפט בהטיה מכוונת עבור מומחיות ספציפית[cite: 227, 233, 248]. [cite_start]בפרויקט זה הגדרנו 3 קובצי Skill ייעודיים בפורמט קובצי Markdown[cite: 236]:
  1. `english-to-hebrew.md` - מומחה לתרגום מאנגלית לעברית.
  2. `hebrew-to-arabic.md` - מומחה לתרגום מעברית לערבית.
  3. `arabic-to-english.md` - מומחה לתרגום מערבית חזרה לאנגלית.
* [cite_start]**כלים (Tools):** תוכנות חיצוניות המאפשרות לסוכן לבצע פעולות חישוב ומדידה[cite: 108, 129, 133]. [cite_start]בפרויקט זה פותח כלי Python ייעודי (`vector_comparison.py`) המודד מרחק וקטורי[cite: 256].

## 3. פירוט כלי המדידה הווקטורי (Vector Comparison Tool)
[cite_start]הסקריפט שפותח מיישם מודל Embedding וחישוב דמיון סמנטי (Cosine Similarity)[cite: 28, 51, 256]. [cite_start]בעוד שחיפוש מסורתי מתבצע לפי טקסט מילולי, מודל שפה מחפש מסמכים ומשמעויות לפי המרחק הווקטורי שלהם במרחב רב-ממדי (חיפוש סמנטי)[cite: 56, 68]. 
* **מדד הדמיון (Similarity Score):** נע בין 0.0 (שוני מוחלט) ל-1.0 (זהות סמנטית מלאה).
* [cite_start]**המרחק הווקטורי (Vector Distance):** מחושב כ-`1 - Similarity Score`[cite: 256]. [cite_start]ככל שהתוצאה קרובה יותר ל-0, כך המשפט הסופי קרוב יותר למקור מבחינת משמעותו הסמנטית, מה שמעיד על שרשרת תרגום איכותית ומדויקת[cite: 268].

## 4. תהליך הרצה ותוצאות עבור משפט הפיילוט
[cite_start]הקלט הראשוני שהוזן למערכת הוא משפט המקור המוצע: **"One for all and all for one"**[cite: 258].

זרימת הנתונים האתוטומטית התבצעה באופן הבא:
1. **שלב א' (אנגלית -> עברית):** הסוכן תרגם את משפט המקור ל-"אחד בשביל כולם, וכולם בשביל אחד".
2. **שלב ב' (עברית -> ערבית):** התוצאה תורגמה ל-"الجميع للواحد والواحد للجميع".
3. **שלב ג' (ערבית -> אנגלית):** המשפט תורגם בחזרה לשפת המקור והניב את הפלט הסופי: **"All for one and one for all"**.

### נתוני המדידה הווקטורית שחושבו בכלי:
* **Original Text:** `One for all and all for one`
* **Final Text:** `All for one and one for all`
* **Similarity Score:** `0.8872`
* **Vector Distance:** `0.1128`

## 5. מסקנות וניתוח
[cite_start]הניסוי מדגים בצורה ברורה את תופעת ה"טלפון השבור" במודלי שפה[cite: 265, 267]. [cite_start]למרות שהמשפט הסופי לא חזר בצורה זהה לחלוטין מילה-במילה למשפט המקור, המרחק הווקטורי נותר קטן מאוד (קרוב ל-0)[cite: 268]. [cite_start]הדבר מוכיח כי מודל השפה מצליח לשמר את ה"ענן הסמנטי" ואת משפחת המשמעויות הקרובות של המשפט לאורך תחנות התרגום השונות, גם כאשר המבנה התחבירי והמילים הספציפיות משתנים קלות[cite: 67, 68, 70].
